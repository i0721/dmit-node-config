# 本轮安全审查记录

范围：Python 迁移及 deploy 准备/升级编排。Rust、Bash、工作流与模板边界人工审查，辅以 Clippy、Cargo 安全公告/许可证/来源检查和恢复测试。不是第三方渗透测试，也不声称能防御已控制 root 的攻击者。

## 已发现并修正

1. 新 TLS 测试探针最初依赖已停止维护的 rustls-pemfile；cargo-deny 检出 RUSTSEC-2025-0134 后已移除，改用 rustls 自带 pki-types 的维护中 PEM 接口，不豁免公告。
2. 准备阶段可能已更改二进制/证书，原服务恢复收据会因此失配。恢复顺序改为先验证并还原原材料，再运行原服务事务与健康检查。
3. CLI 中断后准备子进程可能仍运行。子进程继承部署独占锁，恢复需等其结束；长命令超时或失败清理进程组。测试验证父端释放锁后子进程仍阻止 recover 获取锁。
4. 备份不能只依赖存在性。恢复前校验备份摘要、权限/所有者、完整路径集合及受保护目录；不接受遗漏、重复或逃逸的恢复路径。
5. DNS 请求意图在提交前持久化，返回值随后记入日志。恢复处理请求结果未知和重复重试；并发漂移拒绝覆盖。新记录禁用代理，不改其他名称；CNAME、重复记录和残留 AAAA 需要明确处理。
6. 凭据不进入 argv、公开日志或 node.toml。终端关闭回显，Token 文件须 owner-only，curl 头部通过 stdin；外部工具错误隐藏原始输出。发布流程在提权前构建 Rust 检查器，避免 root 因辅助检查重新安装工具链。
7. 换域名保留旧 TLS/REALITY 名称与 UUID、REALITY 密钥和传输路径；有效证书组不重签。需要重签的兼容 TLS 私钥复用，缓存冲突拒绝静默覆盖。
8. Nginx 官方签名密钥核对、Xray 归档摘要和 usque/acme 提交锁保留；curl 禁止隐式用户配置，生产下载固定 PATH。渲染和应用仍不执行 DNS/ACME 安装操作。
9. ACME 临时 HTTP 服务只提供受限挑战路径，拒绝路径遍历、符号链接文件、越界路径、超大/不完整请求，并限制读取时间。使用已占用的 80 端口前验证原 webroot，不停止其他业务。
10. 新 DNS 可有传播延迟，部署等待受限时间后验证公开 A/AAAA；超时不得报告成功。备份目录树以摘要展示，保持计划可审阅，文件内容和凭据不打印。
11. ACME install-cert 会立即执行 reloadcmd。续期设置增加仅本次配置调用的抑制标志，持锁父进程直接调用原 renew；未来 cron 没有该标志，正常获取锁并校验/reload，避免部署期间自锁失败。
12. 已有 DNS TTL 和注释/标签保留，写前重新检查相关记录；恢复同时检查内容与元数据漂移。兼容升级使用旧快照客户端再次做真实握手；明确的端口/路径/身份变更在预览中列为客户端更新。
13. 换主名称但复用安装目录时停用旧 ACME 续期，保留密钥/缓存，避免后续旧任务覆盖新 SAN。共享 ACME home 发现其他项目证书即要求手动管理；跨 zone 发现清理旧 zone/account 提示，避免 dns_cf 重新读入旧 zone。
14. 自动准备失败保留新签发/注册材料的私密副本，再还原原材料与原服务运行、开机启用状态。已安装包仍保留可执行文件，避免产生与 dpkg 不一致的安装。
15. 全新主机安装后产生的 Nginx 默认入口只在 dpkg 配置摘要与现场摘要都验证后接管；已有入口继续要求显式 takeover。

## 保留边界

- apt 包数据库、新建用户/目录和 CA 已完成签发不能由配置快照撤销；原文件、运行二进制、配置/服务和 DNS 有恢复记录。执行前预览显示此边界。
- 防火墙、供应商网络、第三方 API 权限、CAA、CA 限流、WARP 公网链路和首次实际续期需要真实环境验收；单元或本地 CA 测试不能替代。
- 未知旧服务不猜测导入身份；没有有效原始配置的运行中 Xray 拒绝新建身份接管。0.1 无首次安装基线的卸载限制保持不变。
- 故障注入和本地 DNS/CA 夹具只编入 integration-test；正式发布不启用该 feature。

测试命令与具体结果以最终验收记录和 dist 中本轮日志为准；未执行的生产操作必须单列，不能据本审查记录推断已经上线。
