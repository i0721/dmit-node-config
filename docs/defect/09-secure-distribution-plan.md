# 安全节点分发：需求、设计与实施计划

日期：2026-10-18。状态：本地实施与隔离验收完成，未发布、未上线。范围仅为部署结果、节点页面、订阅与访问凭据，不增加账号系统、管理面板或新的语言。实际结果见 [验收记录](10-secure-distribution-results.md)。

## 现状审查

- `Store::export_format` 读取 current 指针并完整 verify；Xray profiles 与 Mihomo proxies 都由现有 Rust renderer 生成。候选 render 本身不会变成 current。
- host::apply 在入口备份、服务重载、真实握手和默认路由检查之后提交 current/success。恢复保存了原入口和服务状态；自动 deploy 另有证书、DNS 等材料日志。
- Nginx 目前只有站点、ACME、XHTTP 和 WS 路由，无访问鉴权。不可将私密 release 目录或本地导出目录设置为网站 root。
- 事务当前固定五个入口、三个服务，快照模板 1/2 严格重生成。新增端点必须版本化，并显式兼容旧日志和首次安装基线，不能放宽摘要。

## 用户流程与接口

部署交互提供是否启用分发和 Token 自动生成/自行输入。新部署默认启用，旧配置缺省继续保持旧含义，升级向导明确询问启用。成功后输出 HTTPS `/nodes/`、无凭据的订阅地址模板、支持格式、私密 Token 路径及管理命令。首次凭据只写受保护文件并通过控制终端展示，不写 stdout、普通日志或公开报告；无控制终端时仅提示从受保护文件取回。

页面仅有登录表单可匿名访问。Token 在内存中使用 Authorization Bearer 请求，页面刷新即丢弃，不用 Cookie、localStorage 或 URL 保存登录凭据。鉴权后展示当前成功版本节点、复制订阅地址和下载按钮、Mihomo provider 导入及 Xray outbound 导入说明。复制/下载满足当前范围，不增加二维码依赖。

GET `/nodes/sub/mihomo?token=...` 返回现有 Mihomo 节点 provider；GET `/nodes/sub/xray?token=...` 返回现有 Xray profiles 集合，并明确它不是所有客户端通用的订阅协议。页面 API 使用同源 Authorization 头。URL 中凭据仅在用户明确复制订阅时生成；显示为敏感凭据。

`nodectl share status|reveal|rotate|revoke` 管理访问，rotate 支持私密 token-file 或终端无回显输入，默认随机。不得将凭据作为 CLI 参数。撤销后拒绝旧 Token；恢复访问需要显式 rotate，回滚不复活旧 Token。

## 技术与安全边界

1. Nginx 只代理 `/nodes/` 到受权限保护的 Unix socket。同一 nodectl 二进制运行 `share serve`，由一个受限 systemd unit 监督；不增加公网端口、数据库或其他管理接口。
2. 凭据保存在 state-dir/distribution 下、0700 目录及 0600 文件，不放入配置快照或渲染输出。默认使用操作系统随机源产生 256 位值，持久化可恢复的原值及独立鉴权摘要。校验摘要用 constant-time 比较；自定义 Token 必须符合固定长度和字符约束，错误不包含输入。
3. 每次请求重新读取凭据、current 和 success；获取共享主机锁，遇到部署/恢复/卸载事务或指针/成功收据不一致则 503。先鉴权再读取节点，完整 verify 拒绝篡改及候选。只调用现有客户端生成器，不序列化服务端 Secrets。
4. Rust 端点响应（含错误）带 no-store/private、no-referrer、nosniff、frame-ancestors none，不提供 CORS、跳转、第三方资源或分析脚本。CSP 仅允许同源外部脚本、样式和连接，禁止内联脚本。Nginx 路由错误也设置禁缓存及 no-referrer。响应关闭连接，不接受请求体、分块编码、重复鉴权或重复长度字段；限制请求大小、超时、并发与输出大小。
5. Nginx 专用限流区按真实连接 IP 限速、限制突发和并发；Unix socket 仅供 Nginx 连接。代理覆盖客户端身份头，不信任公网自报头。后端不打印原始请求、URI、Token 或内部错误。
6. 专用路径关闭 access log 与缓存；其他路径日志仅保留归一化路径、方法和状态，不记录查询参数、Referer 或原始请求行。为防请求头/请求行解析错误在 location 选择前记录订阅凭据，启用分发时相关 HTTP/TLS server 关闭 error log，保留启动配置检查与 systemd 状态诊断；HTTP 分发路径直接拒绝，不带凭据重定向。集成测试检查正常、超长头、超长 URI 和站点回退请求不会将测试凭据写入日志。
7. 分发认证独立于节点身份。Token 轮换不轮换 UUID、Encryption 或 REALITY 密钥。客户端配置一经下载无法远程撤回；撤销只阻止后续获取，不宣称已下载节点失效。

## 版本、事务与恢复

新增可缺省分发配置，保留旧配置序列化。源码版本为 0.4.0、模板 3；冻结模板 2 和对应模板文件，继续严格验证 0.3.0/0.3.1；模板 1 不变。新服务使用事务的独立可选 sharing 成员记录入口、服务原始状态和首次凭据创建，保留原五入口/三服务集合，旧日志仍按原集合严格恢复。首次旧基线扩展必须依据当次真实观测，不能补造原始状态。

服务在提交 current 前可以启动，但端点在独占部署锁期间只返回不可用；提交后才分发成功版本。失败恢复全部服务和入口。Token 认证状态独立保留，不因完成后的部署 rollback 或旧快照恢复而恢复已撤销凭据。卸载完成后关闭分发并撤销凭据，失败卸载恢复服务事实；保留受保护记录用于恢复审计。

安全恢复边界：恢复不支持分发的旧监听前，先不可逆撤销访问凭据，防止旧模板将仍有效的订阅参数写入日志。关闭/旧版回滚/卸载若在此之后失败，服务与节点配置恢复，但开放订阅需要显式 rotate；预览说明这一点。模板 3 的显式 disabled 状态仍保留无日志的拒绝路径。
