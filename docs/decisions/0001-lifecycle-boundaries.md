# ADR 0001：安装与配置事务分层

状态：采用。

2026-10-18 补充：根目录 install.sh 默认下载并验签正式程序，再进入 Rust `deploy --wizard`。向导在同一会话收集配置、预览并确认部署；Shell 不实现 DNS、证书或服务编排。显式 `--install-only` / `--execute` / `--dry-run` 保留工具安装语义，`nodectl upgrade` 仅安装程序。终端确认与非交互摘要审批共用原事务和锁内复查。

2026-10-17 补充：新增 deploy 作为上述分层步骤的 Rust 编排入口，显式计划审批、准备日志和恢复；复用原 schema/render/check/takeover/apply。系统准备与服务事务的边界不变，手动路径保留。细节见 [交互部署](../automated-deployment.md)。

配置快照不能撤销 CA 签发、DNS 传播或系统软件升级，因此保留准备日志和完整材料备份。签名安装器默认进入向导，部署须经终端确认或显式摘要审批；服务接管仍使用原 takeover 逻辑。卸载恢复真实保存的初始状态，缺失状态时拒绝猜测。

保留 Rust 核心，复用官方软件、Sigstore/cosign 和 SBOM 工具，不实现协议栈和签名算法。首次部署步骤可预览、可审阅、可追踪，但 setup 不代表已配置 DNS、证书和防火墙。新增系统、架构与迁移必须分别提供实际测试证据。
