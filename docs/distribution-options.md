# 附加交付方式评估

本阶段采用两个 Linux 架构的签名 tar.gz 和同一安装/升级入口。与项目的无守护进程 CLI 形态一致，不需要新增公共基础设施。版本选择、信任校验、二进制回退与配置事务相互独立。

Debian .deb 的收益是文件归属和卸载可由 dpkg 查询；风险是 postinst/prerm 改写服务会绕过现有接管与恢复。未来若提供包，只安装 nodectl、文档和补全，不在包脚本中接管服务。移除包前仍由 nodectl uninstall 恢复原配置。必须验证升级和 purge 不删除外部凭据。

APT 仓库需独立签名密钥轮换、索引元数据、HTTPS 托管和持续运维。只有持续发布频率与用户需求能够承担维护成本后再引入；本次不建设公共 APT 服务，也不新建文档站点。现有分层 Markdown 与 Release 足以覆盖当前范围。
