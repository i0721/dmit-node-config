## 外观七项逐项决策

| 设置     | 用户需要理解/比较/操作         | 选择与反馈                                              | 不采用的方案及理由                                                         |
| -------- | ------------------------------ | ------------------------------------------------------- | -------------------------------------------------------------------------- |
| 主题模式 | 工作环境的明暗及系统同步       | 保留已验证的图标卡片，即时改变真实页面                  | 不用Tabs：改变的是一个偏好值，并非面板导航                                 |
| 强调色   | 四个色相，而非颜色名称的长说明 | 预设色样＋名称＋选中边框/表面；值仍由生成Token管理      | 不做自由取色器：当前数据只允许四个预设；不重复画单选圆点                   |
| 界面密度 | 紧凑/标准/宽松的空间节奏       | 三个疏密示意，选择后真实控件同时变化                    | 不嵌套真实表格：放大成本且混淆页面密度与表格密度；明确示意不是精确尺寸承诺 |
| 界面字号 | 阅读大小与整体界面的改变       | 同一句字样三个尺度，标签保持同级；真实页面即时缩放      | 不显示脱离真实体验的百分比滑杆；仍是既有三档枚举                           |
| 内容宽度 | 容器占可用空间的比例           | 比例示意，说明窄屏都使用可用宽度                        | 不把桌面max-width数字当业务API；预览比例不是精确像素                       |
| 动效偏好 | 系统/标准/减少与变化效果       | 紧凑单选＋用户手动ContentSwap；统一Motion Policy降级    | 不自动播放、不建私有timer或reduced-motion监听                              |
| 高对比度 | 辅助文字、边界和焦点差异       | 短单选＋真实文字/边界/Tab焦点；显式high与系统more均验证 | 不用单一开关丢掉系统状态；不以增强焦点冒充全部高对比度                     |

比较项在充足容器中横排；窄容器改为“示意＋文字”纵向列表。不会把全部设置统一做成卡片，
也不将复杂说明压进连体分段控件。色样即使不辨颜色仍有名称，选中状态由HeroUI input
提供；比较图不包含交互后代，并保持aria-hidden，不让装饰进入可访问名称。

## 本轮新确认的问题

- R19-01，P2：长分类字段缺少任务分组。六个分类组合正式Section，短分类维持简洁；
  明确字段标题、说明、选择、即时结果与恢复操作的层级。
- R19-02，P1：搜索仅28项，漏39个实际字段。所有67个字段均可发现及定位；中英名称/
  说明解析、目录唯一性、桌面提示时长和手机时区跳转由回归覆盖。
- R19-03，P1：collapsed状态选择器比手机规则优先级高。1440紧凑侧栏改为390后，
  grid仍为88px＋302px，main只有88px，标题逐字竖排。移动规则覆盖两种侧栏状态，
  保留桌面双列与持久偏好。没有改Token或依赖更高阈值掩盖；八分类及Reference同受益。
- R19-04，P1：Dialog普通确认按钮固定text-white。暗紫背景与白字只有2.76:1，
  高对比度并不能修复错误的前景配对。改用现有text-on-brand，浅色外观保持；
  四强调色×明暗的打开态Axe和键盘焦点验证覆盖真实问题。
- R19-05，P2：320英文大字号虽无横向溢出，主题三列仍将文字挤成逐字换行；分类入口
  同时重复当前分类与长操作说明而被截断。tiles按自身容器回退单列图标行，充足空间保留
  三列卡片；入口只保留清晰的分类/搜索操作。新增主题标签最多两行与入口可见回归，
  不把“无横向溢出”当作可读性证明。公共消费者仍仅settings和UI Elements/forms。

布局使用已有Tailwind容器断点，遵循[官方容器查询](https://tailwindcss.com/docs/responsive-design#container-queries)
的组件可用空间判断；修改前实际复核TailAdmin Form Elements的单选正常/选中/禁用状态。

修改Dialog前实际进入TailAdmin UI Elements/Modals并打开Form In Modal，检查标题、
正文、关闭与保存主次，只学习视觉规律；没有复制外部DOM、CSS、资产或具体数值。
项目仍由HeroUI处理Portal、Focus与Overlay。修正同步进入UI authority，不把当前设置页
变成新的公共规范。Shell问题属于结构断点根因，没有外部视觉尺寸移植。

## 扩展至项目的判断

实际核对UI Elements/forms、actions-selection、overlays、data，以及Page Pattern的
detail-settings和Page Archetype设置表单、Reference资源流程。前者适合字段/交互表达，
后者证明SettingsLayout和真实表单组合，不应被一律替换为视觉选项卡片。普通资源名称仍
是文本输入、通知仍为布尔项；集合工具栏Toggle和字段Radio继续明确分工。

共性缺口已在现有能力收口：值选择可携带装饰比较内容、浮层主操作消费语义前景、Shell
断点不受持久化桌面模式污染、设置搜索覆盖所有实际字段。新业务按Element→Variant→
Composition决策，并在同源UI Elements验证长文/禁用/键盘，不重新实现交互基础。
其余非设置Showcase的elevated内容面仍需按独立场景判断是否合理；不通过修改公共默认
阴影顺带重塑所有消费者。原报告的问题与历史验收边界保留，完整回归与最终对照独立记录。
