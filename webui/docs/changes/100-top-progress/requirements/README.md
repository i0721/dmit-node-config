# 需求：应用级顶部进度条

## 需求摘要

- 客户目标：后台应用在发生路由导航等全局状态转换时，用户能在界面顶部看到轻量、克制的"应用仍在工作"反馈。
- 支撑研究：R100-001。

## 核心行为

- 进度条位于应用 Shell 顶部边缘，覆盖内容之上，不进入文档流。
- 无论网络快慢，每次导航都呈现一次完整的顶部进度反馈周期（出现 → 推进 → 补满 → 淡出）。
- 快速导航也保证最小可见周期，不采用"导航太快就不显示"的门限策略。
- 进度条只前进不回缩：fill 从左侧持续延伸，绝不加载到一半又重新从零加载。
- 慢速导航下 fill 持续推进但不达到 100%，完成后再补满退出。
- 页面转场与顶部进度条共存：前者负责页面视觉连续性，后者负责导航 Pending 反馈。
- 页面内部的数据加载、表格刷新、按钮等待等局部任务不触发全局进度条。

## 非目标

- 不重新设计整个 Loading 体系。
- 不提供业务自由控制颜色、时长、百分比的接口。
- 不把进度条当作页面转场的一部分。
