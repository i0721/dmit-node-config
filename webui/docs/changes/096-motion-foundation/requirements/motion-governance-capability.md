# 动效治理需求

## 1. 客户目标

随着页面转场、加载、折叠、Toast、弹窗等动效增多，产品必须长期保持：动效参数单一权威（不散落数值）、动效语义可读（页面声明"做什么"，不声明"怎么做"）、动效不相互踩踏（不出现多重包裹、生命周期打架），且全部动效对该动效敏感用户可豁免。

## 2. 使用场景

- 新增一个动效（如列表切换过渡）时，能按文档判定"该动效属于哪一类、由哪一层负责、是否已有能力"。
- 页面只写语义（如 `duration-page`、`ScreenTransition`），不写 120ms/240ms、不写 cubic-bezier。
- 弹窗、抽屉、菜单的进出场动效由自身组件负责，无需业务页面包裹动画层。
- 系统开启"减弱动态效果"时，页面转场、弹窗、折叠、加载全部生效统一策略（大位移去掉、时长压短、状态反馈保留）。
- 未来引入动画库或更换转场技术时，只替换底层实现，业务页面语义不变。

## 3. 约束

- 动效参数（时长/缓动/位移/缩放/透明度）与 Reduced Motion Policy 只能来自 `packages/design-system`。
- 禁止万能动画容器；动画容器不得隐式改变页面高度、滚动容器、定位上下文或布局。
- Overlay 动效归 HeroUI/Adapter 内部，禁止在 Modal/Drawer 外再套动画容器。
- Loading 属于产品状态问题，不得做成"加载动画容器"透支未来。

## 4. 非目标

- 不为现有 39 个 UI Element 新增装饰性动画；不改 HeroUI 浮层动画。
- 不新建任何动画原语/容器的实例化（Presence/Transition/Disclosure/AsyncContent 等以用例驱动）。
- 不做旧版系统动效迁移。

## 5. 可验收行为

| 编号    | 行为                    | 验收                                                                                             |
| ------- | ----------------------- | ------------------------------------------------------------------------------------------------ |
| MGC-001 | 动效参数单一权威        | 全仓无业务硬编码时长/缓动/位移字面量（architecture 语义检查；Token 数值只在 design-system 声明） |
| MGC-002 | 页面声明语义不声明参数  | 语义容器与用途 Token 存在且被文档登记；新容器不暴露 duration/easing prop                         |
| MGC-003 | 按类归属清晰            | `docs/motion-foundation.md` 的归属矩阵与代码现状一致（无幻影容器、无错层包裹）                   |
| MGC-004 | Reduced Motion 统一策略 | 全局单一实现；新增配方自动进入覆盖范围（配方登记表要求）                                         |
| MGC-005 | 无万能容器              | AGENTS 条款生效；代码库中不存在跨语义动画 Wrapper                                                |
| MGC-006 | 回归不破坏              | `pnpm check` 全绿（含既有基线文件例外记录）；动效数值不变时视觉基线零变化                        |
| MGC-007 | 未来容器用例先行        | 语义容器目录中每个 Future 项都有触发条件与消费方，无幻影组件                                     |
