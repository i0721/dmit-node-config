# 导航、页面标签与工作恢复

## 客户目标

作为后台用户，我希望每天回来能快速回到上次工作上下文：应用按我的偏好决定启动落在哪个
页面；我打开的多个页面在顶部以标签呈现、可切换/关闭/恢复；我在首页能看到收藏与最近的
入口、可恢复的工作；离开有未保存内容的页面时应用会先确认，不让我丢失输入。

## 使用场景

- 打开根入口 → 按序尝试：有效的工作恢复目标 → 最近页面 → 我指定的首页 → 默认区域首入口
  → 当前首页；直接深链接（如 /settings?category=…）优先，不被启动偏好重定向。
- 从列表点开详情/编辑 → 顶部出现标签；在标签间切换 = 真实路由导航（不缓存页面树）；
  筛选/排序变化不产生重复标签。
- 关闭当前标签 → 按我的策略跳到最近使用/右邻/左邻；关最后一个 → 回默认首页。
- 在编辑页有未保存改动时点其它链接/刷新/关闭 → 应用内先弹离开确认；取消后路由、标签与
  进度都不变；刷新/关闭仅在确有未提交输入时注册浏览器原生提醒（接受平台限制，配合草稿
  恢复）。

## 可验收行为

### 启动目标与最近/收藏

- 登录/首次进入根入口时按"工作恢复 → 最近页面 → 指定首页 → 默认区域首入口 → 当前首页"
  优先级启动；直接深链接不被启动偏好重定向。
- 侧栏与账户菜单提供"设置"入口（同一目标）；账户菜单不再指向旧的偏好页。
- 首页含：收藏入口、最近访问入口、常用命令入口、可恢复工作区段；收藏/最近可记录与显示
  （记录与显示分别可关）；首页不是可拖拽设计器。

### 页面标签

- 顶部标签 = 页面入口的呈现（Route Target + 实体标识），切换仍调用真实 Next Router，
  不缓存 React 页面树；筛选/排序/分页变化不创建重复标签。
- 标签可显示/关闭/恢复；开启标签功能后，当前页面的打开产生标签；默认关闭"跨启动恢复
  标签"，开启后重启恢复上次标签列表（仅引用有效页面）。
- 关闭当前标签策略：最近使用 / 右邻优先 / 左邻优先；最后一个关闭后进入默认首页。
- 新页面打开方式偏好（当前页面 / 浏览器新标签页 / 顶部页面标签）：只作用于声明允许的
  入口；保留 Ctrl/Cmd 点击、下载、外部链接与表单提交的原生语义。

### 离开确认与工作恢复

- 应用内离开确认发生在导航进度开始之前；确认后导航结果区分 完成/取消/失败；取消不改变
  路由、标签与进度条；连续导航与浏览器返回按既有导航生命周期语义收敛。
- 仅当存在未提交输入时注册 beforeunload 原生提醒；浏览器关闭/历史导航/进程终止接受平台
  限制（不承诺原生提醒全覆盖），配合草稿恢复兜底。
- 返回列表时恢复该列表已允许保存的筛选、分页与滚动；显式 URL 条件优先于保存状态；
  普通前进导航按滚动偏好处理；锚点定位保持有效。
- 工作恢复目标必须是有效页面；失效目标（页面被删/不存在）跳过并落到下一优先项，不报错
  中断。
- 首页"可恢复工作区段"列出可恢复的未完成工作；自动恢复工作默认为关，开启后进入根入口时
  先尝试恢复。

## 非目标

- 不缓存 React 页面树/不建第二套 Router/不复制 Next Route Runtime。
- 不承诺浏览器关闭、历史导航、进程终止场景的原生离开提醒全覆盖（[MDN beforeunload]
  (https://developer.mozilla.org/en-US/docs/Web/API/Window/beforeunload_event) 平台限制）。
- 不在第一版把首页扩展为可拖拽设计器。
